# 7.2 Case Management — Design

## Context
Buy ServiceNow/Temporal for MVP orchestration. Temporal workflow orchestrates case lifecycle. Auto-populate case with alert JSON, causal path, counterfactual.

### [human] Design Decisions
- **Buy vs. Build**: ServiceNow for case storage/UI; Temporal for orchestration — buy both for MVP to avoid 6+ month build cycle
- **Temporal Orchestration**: Single workflow per case; activities: `create_case`, `populate_evidence`, `assign_analyst`, `submit_review`
- **Auto-Populate**: On alert P0/P1 → Temporal workflow triggered; case populated with `alert_json` (raw alert), `causal_path` (graph traversal), `counterfactual` (what-if analysis)
- **ServiceNow Integration**: REST API create case; bidirectional sync via Temporal activity

### [agent] resolved
- ServiceNow: Create case via `/api/now/table/sc_case` REST endpoint; store `alert_id`, `priority`, `status`
- Temporal: Workflow `case_orchestration` with activities; signal on analyst action
- Auto-populate: `populate_evidence` activity queries graph for causal path; counterfactual generated by `counterfactual_service` (remove edge → recompute anomaly)
- Data flow: Alert JSON → Temporal → ServiceNow case; causal path from graph DB; counterfactual from simulation

## Architecture
```
P0/P1 Alert → Temporal Workflow → ServiceNow Case
  ├── create_case: REST API → ServiceNow
  ├── populate_evidence: alert_json + causal_path + counterfactual
  ├── assign_analyst: Round-robin to analyst pool
  └── submit_review: Human review → close/forward
```

**Workflow**: `case_orchestration` with 4 activities

## Pushback Hypotheses
1. **H1**: ServiceNow licensing cost is high for MVP. *Mitigation*: Start with Temporal-only for 3 months; migrate to ServiceNow at scale. `# ponytail:` buy vs. build for MVP
2. **H2**: Temporal orchestration adds latency to P0 escalation. *Mitigation*: Parallel activity execution for `create_case` + `populate_evidence`; total workflow < 30s. `# ponytail:` sequential vs. parallel activities

## Open Questions
- What is the ServiceNow API rate limit for case creation?
- Does counterfactual generation add unacceptable latency to the workflow?

## [human] Acceptance
- Case creation from alert < 5s
- Auto-populate fields complete < 10s after workflow start
- Temporal workflow success rate ≥ 99.5%
- ServiceNow case sync latency < 1s
