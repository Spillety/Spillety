# 7. GBDT, калибровка и decision path

Настоящий раздел специфицирует финальный этап decision path — преобразование совокупности retrieval-сигналов, прошедших причинную фильтрацию, в калиброванную вероятностную оценку риска $P(\text{illicit} \mid \text{window})$. Обосновывается выбор Gradient Boosting Decision Trees (GBDT) в реализации LightGBM как court-admissible, калибруемого и CPU-совместимого классификатора, описывается пространство признаков, процедуры калибровки и выбора операционной точки, а также механизм интерпретации предсказаний.

### Термины

| Термин | Определение |
|--------|-------------|
| GBDT | Gradient Boosting Decision Trees — ансамблевый метод, последовательно строящий решающие деревья, каждое из которых аппроксимирует антиградиент функции потерь предыдущего ансамбля |
| LightGBM | Реализация GBDT с гистограммным разбиением, leaf-wise стратегией роста и нативной поддержкой категориальных признаков |
| Decision path | Архитектурный компонент, реализующий финальное отображение признаков в риск-скор; в Spillety — GBDT с последующей калибровкой и пороговой политикой |
| Калибровка | Отображение необработанных скоров модели $s \in \mathbb{R}$ в вероятности $p \in [0,1]$, удовлетворяющие условию $\mathbb{E}[Y \mid \hat{p}=p]=p$ |
| Reliability diagram | Диагностический график зависимости эмпирической частоты $\mathrm{acc}(B_m)$ от средней предсказанной вероятности $\mathrm{conf}(B_m)$ по бинам |
| Brier score | Средний квадрат отклонения предсказанной вероятности от реализовавшегося исхода: $n^{-1}\sum_i (\hat{p}_i-y_i)^2$ |
| ECE | Expected Calibration Error — взвешенное по объёму бинов среднее абсолютное отклонение точности от уверенности |
| Isotonic regression | Непараметрическая монотонная (ступенчатая) регрессия, минимизирующая квадратичную ошибку при ограничении монотонности |
| Beta calibration | Параметрическая калибровка на основе семейства бета-распределений, устойчивая к малым выборкам и экстремальным значениям скоров |
| SHAP | SHapley Additive exPlanations — метод декомпозиции предсказания на аддитивные вклады признаков, основанный на значениях Шепли |
| Target | Целевая переменная модели; в Spillety — $P(\text{illicit in next window})$ |

---

## 7.1. Постановка задачи

К моменту формирования decision path доступны: векторные представления кошельков, кластеры сущностей и множество retrieval-сигналов (расстояния до top-K anchors, типы anchors, графовые и темпоральные признаки), прошедших фильтрацию через causal DAG. Требуется отображение

$$\Phi: \mathcal{X} \subseteq \mathbb{R}^d \to [0,1], \quad \Phi(x) = \hat{P}(\text{illicit} \mid x)$$

удовлетворяющее следующим формальным требованиям:

1. **Court-admissibility и интерпретируемость.** Функция $\Phi$ должна допускать разложение решения на вклады наблюдаемых признаков, верифицируемое регулятором и судом.
2. **Калиброванность.** Выход $\Phi(x)$ интерпретируется как вероятность в частотном смысле, а не как порядковый скор.
3. **Вычислительная совместимость с CPU.** Инференс выполняется без зависимости от GPU при латентности, совместимой с потоковой обработкой транзакций.
4. **Атрибутируемость.** Для каждого алерта формируется вектор вкладов признаков, достаточный для human review и формирования evidence package.

Указанным требованиям удовлетворяет класс GBDT. Использование глубокого обучения в decision path исключается в силу его непрозрачности и регуляторной квалификации как generative AI (SR 26-2); глубокое обучение применяется исключительно на этапе retrieval (обучение GraphSAGE-энкодера) и не участвует в принятии финального решения.

Формальная интерпретация: GBDT представляет собой аддитивный ансамбль $F_M(x) = \sum_{m=1}^{M} \nu \cdot h_m(x)$, где каждое $h_m$ — решающее дерево, аппроксимирующее отрицательный градиент функции потерь, а $\nu$ — learning rate. Последовательная коррекция ошибок предшествующих итераций допускает детерминированную трассировку пути решения.

> **Теоретически мы оцениваем наше решение вот так: CI p-values, E-value, Rosenbaum Γ*, sensemakr R², Brier, ECE, PR-AUC, SHAP** — единый базис оценки; в настоящем разделе операциональны прежде всего Brier, ECE, PR-AUC и SHAP, тогда как CI p-values, E-value, Rosenbaum Γ* и sensemakr R² верифицируют upstream-причинную фильтрацию (раздел 6).

## 7.2. Обоснование выбора GBDT

| Критерий | GBDT | Deep learning |
|----------|------|---------------|
| Интерпретируемость | SHAP values, feature importance, трассировка пути дерева | Непрозрачная параметризация, отсутствие аддитивной декомпозиции |
| Court-admissibility | Установившийся метод в финансовом моделировании | Не соответствует требованию объяснимости |
| Калибруемость | Совместимость с isotonic и beta-калибровкой | Требует дополнительных постулирующих процедур |
| CPU-инференс | Низкая латентность без GPU | Зависимость от ускорителей |
| Малые выборки | Устойчивость при $p(\text{illicit})<0.05$ | Склонность к переобучению |
| Feature engineering | Прозрачное табличное представление | Требует архитектурных индуктивных смещений |

Формальная интерпретация: GBDT принадлежит к классу установленных (well-established) методов, поведение которых предсказуемо при контролируемой сложности ($num\_leaves$, $min\_data\_in\_leaf$, регуляризация). Это свойство является необходимым условием регуляторного соответствия, тогда как глубокие архитектуры в decision path порождают исключение по классу generative AI.

Разделение ролей: GraphSAGE (глубокая модель) — функция представления $\mathcal{G} \to \mathbb{R}^d$; GBDT — функция решения $\mathbb{R}^d \to [0,1]$. Только вторая подлежит требованиям court-admissibility.

## 7.3. Пространство признаков

GBDT обучается на табличных признаках, конструируемых из retrieval-выходов. Размерность итогового вектора $d \approx 50$–$100$, уточняется по анализу feature importance.

### 7.3.1. Расстояния до top-K anchors

Базовая группа признаков — расстояния до $K$ ближайших anchors после причинной фильтрации.

| Признак | Способ вычисления | Формальная интерпретация |
|---------|-------------------|--------------------------|
| $d_1,\dots,d_K$ | Евклидово/косинусное расстояние в embedding space | Мера близости к известным источникам риска |
| mean, min, квантили | Агрегаты по $\{d_i\}$ | Центральная тенденция и хвост распределения близости |
| std | Стандартное отклонение | Дисперсия сигнала близости |

Параметр $K$ определяется по PR-кривой задачи retrieval с выбором по cost-функции (§7.7); теоретически мы оцениваем наше решение вот так: CI p-values, E-value, Rosenbaum Γ*, sensemakr R², Brier, ECE, PR-AUC, SHAP — где PR-AUC является критерием выбора $K$.

## 7.4. Модель: LightGBM

### 7.4.1. Обоснование выбора LightGBM

| Свойство | LightGBM | XGBoost |
|----------|----------|---------|
| Скорость обучения | Высокая (гистограммное разбиение) | Средняя |
| Потребление памяти | Низкое | Среднее |
| Стратегия роста | Leaf-wise (максимальный выигрыш) | Level-wise |
| Категориальные признаки | Нативная поддержка | Требует кодирования |
| CPU-инференс | Высокая производительность | Высокая производительность |

Формальная интерпретация leaf-wise роста: на каждой итерации расщепляется лист с максимальным приростом целевой функции (gain), что при фиксированном числе листьев обеспечивает более точную аппроксимацию, но требует явного контроля сложности через ограничения $num\_leaves$ и $min\_data\_in\_leaf$ для предотвращения переобучения.

### 7.4.2. Гиперпараметры и формальный выбор

| Параметр | Диапазон кандидатов | Роль |
|----------|---------------------|------|
| num_leaves | $\{31, 63, 127\}$ | Контроль сложности дерева |
| learning_rate | $0.01$–$0.1$ | Шаг градиентного обновления |
| n_estimators | $100$–$1000$ | Число итераций бустинга |
| min_data_in_leaf | $20$–$100$ | Регуляризация листа |
| feature_fraction | $0.7$–$0.9$ | Стохастический отбор признаков |
| bagging_fraction | $0.7$–$0.9$ | Стохастический отбор наблюдений |
| lambda_l1, lambda_l2 | $0$–$1$ | $L_1$/$L_2$-регуляризация |

**Формальный выбор $num\_leaves \in \{31, 63, 127\}$ по PR-AUC.** Три кандидатные конфигурации ($31$ — консервативная, $63$ — умеренная, $127$ — высокая сложность) сравниваются на hold-out temporal split по критерию PR-AUC (предпочтительнее ROC-AUC при дисбалансе классов). Процедура: обучение LightGBM с фиксированными прочими гиперпараметрами, оценка PR-AUC на hold-out, построение bootstrap CI для разности PR-AUC между конфигурациями. Выбирается минимальная сложность, не уступающая более сложным по верхней границе CI (принцип парсимонии при статистической неразличимости). Теоретически мы оцениваем наше решение вот так: CI p-values, E-value, Rosenbaum Γ*, sensemakr R², Brier, ECE, PR-AUC, SHAP — где PR-AUC является решающим критерием выбора $num\_leaves$.

Оптимизация прочих гиперпараметров выполняется посредством Optuna/Hyperopt на validation set с целевым функционалом PR-AUC на hold-out temporal split.

### 7.4.3. Обучение

**Данные.** Elliptic++, IBM AML, AMLSim с временным разбиением (temporal split) для исключения информационной утечки (look-ahead bias).

**Target.** 

$$\text{Target} = \mathbb{I}[\text{illicit in next window}],$$

где illicit определяется дизъюнкцией:

$$\text{illicit} := \text{OFAC-listed} \lor \text{court-convicted} \lor \text{under active investigation}$$

— формальное определение, фиксирующее семантику предсказываемой вероятности $P(\text{illicit in next window})$.

**Классовый дисбаланс.** Доля illicit $<5\%$. Применяются: параметр `scale_pos_weight`, модификация функции потерь типа focal loss для GBDT, осторожный oversampling меньшинства (с контролем переобучения).

**Верификация.** Сравнение PR-AUC на hold-out с baseline (XGBoost на Elliptic++); теоретически мы оцениваем наше решение вот так: CI p-values, E-value, Rosenbaum Γ*, sensemakr R², Brier, ECE, PR-AUC, SHAP.

## 7.5. Калибровка

### 7.5.1. Постановка проблемы

Некалиброванный выход GBDT $s = F_M(x)$ является монотонным преобразованием log-odds, но не удовлетворяет калибровочному тождеству $\mathbb{E}[Y \mid s]= \sigma(s)$. Следовательно, $s=0.8$ не имплицирует, что $80\%$ объектов со скором $0.8$ принадлежат классу illicit.

Необходимость калибровки обусловлена: (i) интерпретируемостью для аналитика; (ii) корректностью cost-оптимального выбора порога по PR-кривой, требующей вероятностной шкалы; (iii) регуляторным требованием SR 26-2.

### 7.5.2. Методы калибровки

**Isotonic regression.** Непараметрическая монотонная ступенчатая функция $f: \mathbb{R} \to [0,1]$, решающая задачу

$$
\min_{f \text{ монотонна}} \sum_{i=1}^{n} (y_i - f(\hat{p}_i))^2,
$$

где $\hat{p}_i$ — некалиброванный скор, $y_i \in \{0,1\}$ — метка. Формальная интерпретация: оптимальная $L_2$-аппроксимация при ограничении изотонности (pool adjacent violators algorithm). Достоинство — отсутствие параметрических допущений о форме; ограничение — требование большого объёма калибровочной выборки и нестабильность на хвостах распределения.

**Beta calibration.** Параметрическое семейство

$$
f(\hat{p}) = \frac{1}{1 + \exp\left(-a \log \frac{\hat{p}}{1 - \hat{p}} - b \log \hat{p} - c\right)},
$$

где параметры $a,b,c$ оцениваются на validation set максимизацией правдоподобия. Формальная интерпретация: обобщение Platt scaling с гибкостью бета-распределения; устойчивость к малым выборкам и экстремальным скорам при цене параметрического допущения.

### 7.5.3. Формальный выбор метода калибровки: isotonic vs beta по ECE/Brier (bootstrap)

Критерий выбора — минимизация ECE при контроле Brier score.

Процедура:

1. Временное разбиение train/validation/test.
2. Обучение GBDT на train.
3. Оценка параметров isotonic и beta-калибровки на validation.
4. Вычисление ECE и Brier на test.
5. Построение bootstrap CI (1000 репликаций) для разностей $\Delta\text{ECE} = \text{ECE}_{\text{iso}} - \text{ECE}_{\text{beta}}$ и $\Delta\text{Brier}$.
6. Выбор метода с статистически значимо меньшим ECE (верхняя граница CI для $\Delta$ не пересекает нуль); при статистической неразличимости предпочтение отдаётся beta-калибровке как более устойчивой к малым выборкам.

Теоретически мы оцениваем наше решение вот так: CI p-values, E-value, Rosenbaum Γ*, sensemakr R², Brier, ECE, PR-AUC, SHAP — где Brier и ECE с их bootstrap CI являются решающими для выбора между isotonic и beta.

Диагностика корректности — reliability diagram на test: близость ломаной к диагонали $y=x$ свидетельствует о калиброванности.

## 7.6. Метрики калибровки

### 7.6.1. Brier score

$$
\text{Brier} = \frac{1}{n} \sum_{i=1}^{n} (\hat{p}_i - y_i)^2
$$

Формальная интерпретация: $0$ — идеальная калибровка и дискриминация; $0.25$ — случайный предиктор при сбалансированных классах. При дисбалансе классов Brier смещён к base rate; обязательным является сравнение с тривиальным предиктором $\hat{p}_i \equiv \bar{y}$. Теоретически мы оцениваем наше решение вот так: CI p-values, E-value, Rosenbaum Γ*, sensemakr R², Brier, ECE, PR-AUC, SHAP.

### 7.6.2. ECE (Expected Calibration Error)

$$
\text{ECE} = \sum_{m=1}^{M} \frac{|B_m|}{n} \left| \text{acc}(B_m) - \text{conf}(B_m) \right|,
$$

где $B_m$ — бин $m$ (фиксированное число бинов $M=10$–$15$), $\text{acc}(B_m)$ — эмпирическая точность в бине, $\text{conf}(B_m)$ — средняя предсказанная вероятность. Формальная интерпретация: взвешенное $L_1$-отклонение reliability-диаграммы от диагонали; $0$ — идеальная калибровка, $>0.10$ — неудовлетворительная. Теоретически мы оцениваем наше решение вот так: CI p-values, E-value, Rosenbaum Γ*, sensemakr R², Brier, ECE, PR-AUC, SHAP.

### 7.6.3. Reliability diagram

Формальная интерпретация: график отображения $\text{conf}(B_m) \mapsto \text{acc}(B_m)$; точки выше диагонали соответствуют недооценке риска (underconfidence), ниже — переоценке (overconfidence). Отклонение от диагонали квантифицируется ECE.

## 7.7. Выбор операционной точки (operating point)

### 7.7.1. PR-кривая

После калибровки для каждого порога $\tau \in [0,1]$ вычисляются

$$
\text{Precision}(\tau) = \frac{TP(\tau)}{TP(\tau) + FP(\tau)}, \qquad
\text{Recall}(\tau) = \frac{TP(\tau)}{TP(\tau) + FN(\tau)}.
$$

PR-кривая $\{\;(\text{Recall}(\tau), \text{Precision}(\tau))\;\}_{\tau}$ характеризует компромисс между точностью детекции и её полнотой. Формальная интерпретация: повышение $\tau$ монотонно увеличивает precision за счёт снижения recall. Теоретически мы оцениваем наше решение вот так: CI p-values, E-value, Rosenbaum Γ*, sensemakr R², Brier, ECE, PR-AUC, SHAP — где PR-AUC агрегирует качество ранжирования по всем порогам.

### 7.7.2. Cost-функция

Оптимальный порог $\tau^*$ определяется минимизацией ожидаемых издержек

$$
\text{Cost}(\tau) = C_{FP} \cdot FP(\tau) + C_{FN} \cdot FN(\tau),
$$

где $C_{FP}$ — стоимость ложноположительного срабатывания (время аналитика $\times$ ставка), оцениваемая по операционным данным; $C_{FN}$ — стоимость ложноотрицательного (ожидаемый регуляторный штраф $\times$ вероятность реализации), оцениваемая по публичным enforcement actions и внутренней risk-модели.

### 7.7.3. Бюджетное ограничение

При $C_{FN}/C_{FP} \gg 1$ решение $\tau^* \to 0$ вырождается в тривиальную политику алерта на всех объектах. Вводится бюджетное ограничение

$$
\text{Alerts}(\tau) \leq B,
$$

где $B$ — пропускная способность аналитического подразделения. Порог выбирается как максимизирующий recall при выполнении ограничения.

### 7.7.4. Пороги Tier 1/2/3

| Tier | Условие | Действие |
|------|---------|----------|
| Tier 1 | $\text{score} > \tau_1 \land \text{causal passed} \land \text{E-value} > 2.0 \land \Gamma^* > 1.5$ | auto-block + SAR + human review |
| Tier 2 | $\tau_2 < \text{score} \leq \tau_1$ | analyst review |
| Tier 3 | $\tau_3 < \text{score} \leq \tau_2$ | async review, no blocking |
| Auto-clear | $\text{score} \leq \tau_3$ | no action, logged |

Пороги $\tau_1,\tau_2,\tau_3$ определяются из PR-кривой минимизацией Cost при бюджетном ограничении; $\tau_1$ — порог автоблокировки, $\tau_2$ — ручного рассмотрения, $\tau_3$ — асинхронного рассмотрения. Для Tier 1 дополнительно применяется альтернативный порог E-value $>2.5$ в консервативном режиме (см. §6.5.1).

## 7.8. Интерпретируемость: SHAP values

### 7.8.1. Формализация SHAP

Для предсказания $f(x)$ и признака $i$ значение Шепли определяется как

$$
\phi_i = \sum_{S \subseteq N \setminus \{i\}} \frac{|S|!\,(|N| - |S| - 1)!}{|N|!}\bigl(f(S \cup \{i\}) - f(S)\bigr),
$$

где $N$ — множество признаков, $S$ — коалиция. Выполняется свойство эффективности: $\sum_{i \in N} \phi_i = f(x) - \mathbb{E}[f(X)]$. Формальная интерпретация: $\phi_i$ — маргинальный вклад признака $i$, усреднённый по всем перестановкам включения признаков.

Теоретически мы оцениваем наше решение вот так: CI p-values, E-value, Rosenbaum Γ*, sensemakr R², Brier, ECE, PR-AUC, SHAP — где SHAP верифицирует атрибутируемость и court-admissibility решения.

### 7.8.2. Применение в Spillety

Для каждого алерта вычисляются SHAP values топ-10 признаков и включаются в evidence JSON:

```json
{
  "shap_values": {
    "distance_to_nearest_OFAC": -0.34,
    "causal_filter_pass_rate": 0.28,
    "e_value_max": 0.15,
    "anchor_source_diversity": 0.12
  }
}
```

Формальная интерпретация: знак $\phi_i$ указывает направление вклада в риск-скор, абсолютная величина — относительную важность. Для LightGBM применяется алгоритм TreeSHAP, обеспечивающий точное вычисление за полиномиальное время.

## 7.10. Ограничения

1. **Классовый дисбаланс.** Доля illicit $<5\%$ индуцирует смещение к majority class; коррекция через `scale_pos_weight`, focal loss и oversampling не элиминирует полностью риск переобучения на меньшинстве.
2. **Темпоральный дрейф.** Распределение $P(X,Y)$ эволюционирует при появлении новых типологий (ZK-mixers, cross-chain bridges); требуется периодическое переобучение (см. раздел 8) с верификацией по PR-AUC и ECE на скользящем окне.
3. **Калибровка на малых выборках.** Isotonic regression требует объёма, достаточного для стабильной оценки ступеней; beta-калибровка устойчивее, но ограничена параметрическим семейством. Выбор isotonic vs beta по ECE/Brier bootstrap частично смягчает компромисс.
4. **Вычислительная сложность SHAP.** Для ансамблей большой мощности точное вычисление $\phi_i$ затратно; применяется аппроксимация TreeSHAP с контролируемой погрешностью.
5. **Отсутствие причинной интерпретации SHAP.** Значения $\phi_i$ отражают ассоциативный вклад в предсказание $\hat{P}$, но не причинный эффект признака на исход; причинная интерпретация требует DAG-формализма (раздел 6, CI p-values, E-value, Rosenbaum Γ*, sensemakr R²).
6. **Зависимость target от дефиниции illicit.** Определение $ \text{OFAC-listed} \lor \text{court-convicted} \lor \text{under active investigation}$ чувствительно к регуляторным изменениям; модификация дефиниции требует респецификации target и ревалидации по Brier, ECE, PR-AUC, SHAP.

---

**Резюме.** GBDT в реализации LightGBM является финальной моделью decision path, отображающей табличные признаки retrieval в калиброванную вероятность $P(\text{illicit in next window})$. Пространство признаков включает расстояния до anchors, типологические, графовые, темпоральные и контекстуальные группы, а также метрики чувствительности. Калибровка выбирается между isotonic и beta по минимуму ECE/Brier с верификацией через bootstrap CI; сложность деревьев ($num\_leaves \in \{31,63,127\}$) — по максимуму PR-AUC с bootstrap CI. Интерпретация обеспечивается SHAP-декомпозицией.

| Компонент | Функция | Формальный результат |
|-----------|---------|----------------------|
| LightGBM | Финальная модель | $\hat{P}(\text{illicit in next window})$, $num\_leaves \in \{31,63,127\}$ по PR-AUC bootstrap |
| Feature engineering | Конструирование признаков из retrieval | Вектор $x \in \mathbb{R}^{50\text{–}100}$ |
| Isotonic / beta calibration | Калибровка скоров | Калиброванные $\hat{p}$, выбор по ECE/Brier bootstrap |
| Brier, ECE | Метрики калибровки | Количественная оценка отклонения от $y=x$ |
| PR-curve + cost | Выбор операционной точки | Пороги $\tau_1,\tau_2,\tau_3$, PR-AUC |
| SHAP values | Атрибуция предсказания | $\phi_i$, evidence JSON |

Теоретически мы оцениваем наше решение вот так: CI p-values, E-value, Rosenbaum Γ*, sensemakr R², Brier, ECE, PR-AUC, SHAP — где Brier, ECE и PR-AUC верифицируют калибровочную и дискриминативную корректность, SHAP — интерпретируемость, а CI p-values, E-value, Rosenbaum Γ* и sensemakr R² — причинную обоснованность upstream-фильтра.
