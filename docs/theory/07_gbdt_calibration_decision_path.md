# 7. GBDT, калибровка и decision path

Финальный этап decision path — преобразование retrieval-сигналов, прошедших причинную фильтрацию, в калиброванную вероятностную оценку риска $P(\text{illicit} \mid \text{window})$. Обоснование выбора Gradient Boosting Decision Trees (GBDT) в реализации LightGBM как court-admissible, калибруемого и CPU-совместимого классификатора, пространство признаков, процедуры калибровки и выбора операционной точки, механизм интерпретации предсказаний.

### Термины

| Термин | Определение |
|--------|-------------|
| GBDT | Gradient Boosting Decision Trees — ансамблевый метод, последовательно строящий решающие деревья, каждое из которых аппроксимирует антиградиент функции потерь предыдущего ансамбля |
| LightGBM | Реализация GBDT с гистограммным разбиением, leaf-wise стратегией роста и нативной поддержкой категориальных признаков |
| Decision path | Архитектурный компонент, реализующий финальное отображение признаков в риск-скор; в Spillety — GBDT с последующей калибровкой и пороговой политикой |
| Калибровка | Отображение необработанных скоров модели $s \in \mathbb{R}$ в вероятности $p \in [0,1]$, удовлетворяющие $\mathbb{E}[Y \mid \hat{p}=p]=p$ |
| Reliability diagram | Диагностический график зависимости эмпирической частоты $\mathrm{acc}(B_m)$ от средней предсказанной вероятности $\mathrm{conf}(B_m)$ по бинам |
| Brier score | Средний квадрат отклонения предсказанной вероятности от реализовавшегося исхода |
| ECE | Expected Calibration Error — взвешенное по объёму бинов среднее абсолютное отклонение точности от уверенности |
| Isotonic regression | Непараметрическая монотонная (ступенчатая) регрессия, минимизирующая квадратичную ошибку при ограничении монотонности |
| Beta calibration | Параметрическая калибровка на основе семейства бета-распределений, устойчивая к малым выборкам и экстремальным значениям скоров |
| SHAP | SHapley Additive exPlanations — метод декомпозиции предсказания на аддитивные вклады признаков, основанный на значениях Шепли |
| Target | Целевая переменная модели; в Spillety — $P(\text{illicit in next window})$ |

---

## 7.1. Постановка задачи

К моменту формирования decision path доступны: векторные представления кошельков, кластеры сущностей и множество retrieval-сигналов (расстояния до top-K anchors, типы anchors, графовые и темпоральные признаки), прошедших фильтрацию через causal DAG. Требуется отображение

$$\Phi: \mathcal{X} \subseteq \mathbb{R}^d \to [0,1], \quad \Phi(x) = \hat{P}(\text{illicit} \mid x)$$

удовлетворяющее требованиям:

1. **Court-admissibility и интерпретируемость.** Разложение решения на вклады наблюдаемых признаков, верифицируемое регулятором и судом.
2. **Калиброванность.** Выход $\Phi(x)$ интерпретируется как вероятность в частотном смысле, а не как порядковый скор.
3. **Вычислительная совместимость с CPU.** Инференс без зависимости от GPU при латентности, совместимой с потоковой обработкой.
4. **Атрибутируемость.** Для каждого алерта формируется вектор вкладов признаков для human review и evidence package.

Указанным требованиям удовлетворяет класс GBDT. Глубокое обучение в decision path исключается в силу непрозрачности и регуляторной квалификации как generative AI (SR 26-2); глубокое обучение применяется исключительно на этапе retrieval (обучение GraphSAGE-энкодера).

GBDT — аддитивный ансамбль $F_M(x) = \sum_{m=1}^{M} \nu \cdot h_m(x)$, где каждое $h_m$ — решающее дерево, аппроксимирующее отрицательный градиент функции потерь, а $\nu$ — learning rate. Последовательная коррекция ошибок предшествующих итераций допускает детерминированную трассировку пути решения.

Оценка: CI p-values, E-value, Rosenbaum Γ*, sensemakr R², Brier, ECE, PR-AUC, SHAP. В настоящем разделе операциональны Brier, ECE, PR-AUC и SHAP; CI p-values, E-value, Rosenbaum Γ* и sensemakr R² верифицируют upstream-причинную фильтрацию (раздел 6).

## 7.2. Обоснование выбора GBDT

| Критерий | GBDT | Deep learning |
|----------|------|---------------|
| Интерпретируемость | SHAP values, feature importance, трассировка пути дерева | Непрозрачная параметризация |
| Court-admissibility | Установившийся метод в финансовом моделировании | Не соответствует требованию объяснимости |
| Калибруемость | Совместимость с isotonic и beta-калибровкой | Требует дополнительных постулирующих процедур |
| CPU-инференс | Низкая латентность без GPU | Зависимость от ускорителей |
| Малые выборки | Устойчивость при $p(\text{illicit})<0.05$ | Склонность к переобучению |
| Feature engineering | Прозрачное табличное представление | Требует архитектурных индуктивных смещений |

GBDT — класс установленных методов, поведение которых предсказуемо при контролируемой сложности ($num\_leaves$, $min\_data\_in\_leaf$, регуляризация). Это необходимое условие регуляторного соответствия.

**Разделение ролей:** GraphSAGE — функция представления $\mathcal{G} \to \mathbb{R}^d$; GBDT — функция решения $\mathbb{R}^d \to [0,1]$. Только вторая подлежит требованиям court-admissibility.

## 7.3. Пространство признаков

GBDT обучается на табличных признаках, конструируемых из retrieval-выходов. Размерность итогового вектора $d \approx 50$–$100$, уточняется по анализу feature importance.

### 7.3.1. Расстояния до top-K anchors

| Признак | Способ вычисления | Интерпретация |
|---------|-------------------|---------------|
| $d_1,\dots,d_K$ | Евклидово/косинусное расстояние в embedding space | Мера близости к известным источникам риска |
| mean, min, квантили | Агрегаты по $\{d_i\}$ | Центральная тенденция и хвост распределения близости |
| std | Стандартное отклонение | Дисперсия сигнала близости |

Параметр $K$ определяется по PR-кривой задачи retrieval с выбором по cost-функции.

### 7.3.2. Типы anchors

| Признак | Способ вычисления | Интерпретация |
|---------|-------------------|---------------|
| anchor_types_in_top_K | Частоты типов в top-K | Типологическая структура ближайших источников риска |
| anchor_source_diversity | Число уникальных источников | Широта ассоциаций |
| distance_to_nearest_OFAC | $\min_{a \in \mathcal{A}_{\text{OFAC}}} d(w,a)$ | Прямая санкционная близость |
| distance_to_nearest_mixer | $\min_{a \in \mathcal{A}_{\text{mixer}}} d(w,a)$ | Косвенная близость к механизмам сокрытия |
| distance_to_nearest_exchange | $\min_{a \in \mathcal{A}_{\text{ex}}} d(w,a)$ | Инфраструктурная близость |

### 7.3.3. Графовые признаки

| Признак | Способ вычисления | Интерпретация |
|---------|-------------------|---------------|
| PageRank | Итеративный алгоритм на транзакционном графе | Центральность и структурная важность узла |
| in_degree, out_degree | Подсчёт входящих/исходящих рёбер | Мера активности |

| Признак | Способ вычисления | Интерпретация |

## 7.4. Модель: LightGBM

### 7.4.1. Обоснование выбора LightGBM

| Свойство | LightGBM | XGBoost |
|----------|----------|---------|
| Скорость обучения | Высокая (гистограммное разбиение) | Средняя |
| Потребление памяти | Низкое | Среднее |
| Стратегия роста | Leaf-wise (максимальный выигрыш) | Level-wise |
| Категориальные признаки | Нативная поддержка | Требует кодирования |
| CPU-инференс | Высокая производительность | Высокая производительность |

Leaf-wise рост: на каждой итерации расщепляется лист с максимальным приростом целевой функции (gain), что при фиксированном числе листьев обеспечивает более точную аппроксимацию, но требует явного контроля сложности через $num\_leaves$ и $min\_data\_in\_leaf$.

### 7.4.2. Гиперпараметры и выбор

| Параметр | Диапазон кандидатов | Роль |
|----------|---------------------|------|
| num_leaves | $\{31, 63, 127\}$ | Контроль сложности дерева |
| learning_rate | $0.01$–$0.1$ | Шаг градиентного обновления |
| n_estimators | $100$–$1000$ | Число итераций бустинга |
| min_data_in_leaf | $20$–$100$ | Регуляризация листа |
| feature_fraction | $0.7$–$0.9$ | Стохастический отбор признаков |
| bagging_fraction | $0.7$–$0.9$ | Стохастический отбор наблюдений |
| lambda_l1, lambda_l2 | $0$–$1$ | $L_1$/$L_2$-регуляризация |

**Выбор $num\_leaves \in \{31, 63, 127\}$ по PR-AUC.** Три кандидатные конфигурации сравниваются на hold-out temporal split. Процедура: обучение LightGBM с фиксированными прочими гиперпараметрами, оценка PR-AUC на hold-out, построение bootstrap CI для разности. Выбирается минимальная сложность, не уступающая более сложным по верхней границе CI (принцип парсимонии).

Оптимизация прочих гиперпараметров — через Optuna/Hyperopt на validation set с целевым функционалом PR-AUC на hold-out temporal split.

### 7.4.3. Обучение

**Данные.** Elliptic++, IBM AML, AMLSim с временным разбиением (temporal split) для исключения look-ahead bias.

**Target:**

$$\text{Target} = \mathbb{I}[\text{illicit in next window}]$$

где illicit определяется дизъюнкцией:

$$\text{illicit} := \text{OFAC-listed} \lor \text{court-convicted} \lor \text{under active investigation}$$

**Классовый дисбаланс.** Доля illicit $<5\%$. Применяются: `scale_pos_weight`, focal loss для GBDT, осторожный oversampling меньшинства.

**Верификация.** Сравнение PR-AUC на hold-out с baseline (XGBoost на Elliptic++).

## 7.5. Калибровка

### 7.5.1. Постановка проблемы

Некалиброванный выход GBDT $s = F_M(x)$ является монотонным преобразованием log-odds, но не удовлетворяет калибровочному тождеству $\mathbb{E}[Y \mid s]= \sigma(s)$. $s=0.8$ не имплицирует, что $80\%$ объектов со скором $0.8$ принадлежат классу illicit.

Необходимость калибровки: (i) интерпретируемость для аналитика; (ii) корректность cost-оптимального выбора порога; (iii) регуляторное требование SR 26-2.

### 7.5.2. Методы калибровки

**Isotonic regression.** Непараметрическая монотонная ступенчатая функция $f: \mathbb{R} \to [0,1]$:

$$
\min_{f \text{ монотонна}} \sum_{i=1}^{n} (y_i - f(\hat{p}_i))^2
$$

Достоинство — отсутствие параметрических допущений; ограничение — требование большого объёма калибровочной выборки и нестабильность на хвостах.

**Beta calibration.** Параметрическое семейство:

$$
f(\hat{p}) = \frac{1}{1 + \exp\left(-a \log \frac{\hat{p}}{1 - \hat{p}} - b \log \hat{p} - c\right)}
$$

Параметры $a,b,c$ оцениваются на validation set максимизацией правдоподобия. Устойчивость к малым выборкам и экстремальным скорам при цене параметрического допущения.

### 7.5.3. Выбор метода калибровки: isotonic vs beta

Критерий — минимизация ECE при контроле Brier score.

Процедура:

1. Временное разбиение train/validation/test.
2. Обучение GBDT на train.
3. Оценка параметров isotonic и beta-калибровки на validation.
4. Вычисление ECE и Brier на test.
5. Построение bootstrap CI (1000 репликаций) для разностей $\Delta\text{ECE}$ и $\Delta\text{Brier}$.
6. Выбор метода с статистически значимо меньшим ECE (верхняя граница CI для $\Delta$ не пересекает нуль); при неразличимости — предпочтение beta-калибровке как более устойчивой к малым выборкам.

Диагностика — reliability diagram на test: близость ломаной к диагонали $y=x$ свидетельствует о калиброванности.

## 7.6. Метрики калибровки

### 7.6.1. Brier score

$$
\text{Brier} = \frac{1}{n} \sum_{i=1}^{n} (\hat{p}_i - y_i)^2
$$

$0$ — идеальная калибровка и дискриминация; $0.25$ — случайный предиктор при сбалансированных классах. При дисбалансе Brier смещён к base rate; обязательно сравнение с тривиальным предиктором $\hat{p}_i \equiv \bar{y}$.

### 7.6.2. ECE

$$
\text{ECE} = \sum_{m=1}^{M} \frac{|B_m|}{n} \left| \text{acc}(B_m) - \text{conf}(B_m) \right|
$$

$B_m$ — бин $m$ ($M=10$–$15$), $\text{acc}(B_m)$ — эмпирическая точность, $\text{conf}(B_m)$ — средняя предсказанная вероятность. $0$ — идеальная калибровка, $>0.10$ — неудовлетворительная.

### 7.6.3. Reliability diagram

График отображения $\text{conf}(B_m) \mapsto \text{acc}(B_m)$. Точки выше диагонали — недооценка риска (underconfidence), ниже — переоценка (overconfidence). Отклонение квантифицируется ECE.

## 7.7. Выбор операционной точки (operating point)

### 7.7.1. PR-кривая

После калибровки для каждого порога $\tau \in [0,1]$:

$$
\text{Precision}(\tau) = \frac{TP(\tau)}{TP(\tau) + FP(\tau)}, \qquad
\text{Recall}(\tau) = \frac{TP(\tau)}{TP(\tau) + FN(\tau)}.
$$

PR-кривая характеризует компромисс между точностью и полнотой. Повышение $\tau$ монотонно увеличивает precision за счёт снижения recall.

### 7.7.2. Cost-функция

Оптимальный порог:

$$
\text{Cost}(\tau) = C_{FP} \cdot FP(\tau) + C_{FN} \cdot FN(\tau)
$$

- $C_{FP}$ — стоимость ложноположительного срабатывания (время аналитика × ставка).
- $C_{FN}$ — стоимость ложноотрицательного (ожидаемый регуляторный штраф × вероятность реализации).

### 7.7.3. Бюджетное ограничение

При $C_{FN}/C_{FP} \gg 1$ решение $\tau^* \to 0$ вырождается в тривиальную политику алерта на всех объектах. Вводится ограничение:

$$
\text{Alerts}(\tau) \leq B
$$

где $B$ — пропускная способность аналитического подразделения. Порог выбирается как максимизирующий recall при выполнении ограничения.

### 7.7.4. Пороги Tier 1/2/3

| Tier | Условие | Действие |
|------|---------|----------|
| Tier 1 | $\text{score} > \tau_1 \land \text{causal passed} \land \text{E-value} > 2.0 \land \Gamma^* > 1.5$ | auto-block + SAR + human review |
| Tier 2 | $\tau_2 < \text{score} \leq \tau_1$ | analyst review |
| Tier 3 | $\tau_3 < \text{score} \leq \tau_2$ | async review, no blocking |
| Auto-clear | $\text{score} \leq \tau_3$ | no action, logged |

Пороги $\tau_1,\tau_2,\tau_3$ определяются из PR-кривой минимизацией Cost при бюджетном ограничении. Для Tier 1 дополнительно применяется альтернативный порог E-value $>2.5$ в консервативном режиме.

## 7.8. Интерпретируемость: SHAP values

### 7.8.1. Формализация SHAP

Для предсказания $f(x)$ и признака $i$:

$$
\phi_i = \sum_{S \subseteq N \setminus \{i\}} \frac{|S|!\,(|N| - |S| - 1)!}{|N|!}\bigl(f(S \cup \{i\}) - f(S)\bigr)
$$

$N$ — множество признаков, $S$ — коалиция. Свойство эффективности: $\sum_{i \in N} \phi_i = f(x) - \mathbb{E}[f(X)]$. $\phi_i$ — маргинальный вклад признака $i$, усреднённый по всем перестановкам включения.

### 7.8.2. Применение в Spillety

Для каждого алерта вычисляются SHAP values топ-10 признаков и включаются в evidence JSON:

```json
{
  "shap_values": {
    "distance_to_nearest_OFAC": -0.34,
    "causal_filter_pass_rate": 0.28,
    "e_value_max": 0.15,
    "anchor_source_diversity": 0.12
  }
}
```

Знак $\phi_i$ указывает направление вклада в риск-скор, абсолютная величина — относительную важность. Для LightGBM применяется TreeSHAP, обеспечивающий точное вычисление за полиномиальное время.

## 7.10. Ограничения

1. **Классовый дисбаланс.** Доля illicit $<5\%$ индуцирует смещение к majority class; коррекция через `scale_pos_weight`, focal loss и oversampling не элиминирует полностью риск переобучения.
2. **Темпоральный дрейф.** Распределение $P(X,Y)$ эволюционирует при появлении новых типологий; требуется периодическое переобучение с верификацией по PR-AUC и ECE на скользящем окне.
3. **Калибровка на малых выборках.** Isotonic regression требует объёма для стабильной оценки ступеней; beta-калибровка устойчивее, но ограничена параметрическим семейством. Выбор isotonic vs beta по ECE/Brier bootstrap частично смягчает компромисс.
4. **Вычислительная сложность SHAP.** Для ансамблей большой мощности точное вычисление $\phi_i$ затратно; применяется аппроксимация TreeSHAP.
5. **Отсутствие причинной интерпретации SHAP.** Значения $\phi_i$ отражают ассоциативный вклад, но не причинный эффект; причинная интерпретация требует DAG-формализма (раздел 6).
6. **Зависимость target от дефиниции illicit.** Определение $\text{OFAC-listed} \lor \text{court-convicted} \lor \text{under active investigation}$ чувствительно к регуляторным изменениям; модификация требует респецификации target и ревалидации.
