# K-BRAIN

Комментарии в коде — на английском. Всё остальное — на русском.
Не удаляй файлы пользователя, если они в .gitignore.
Все комментарии строго по шаблону `K-BRAIN/SKILLS/comments.md`.
Для решения больших задач используй subagents. 
Для разработки используй SKILL `K-BRAIN/SKILLS/dvelopment.md`.
Для code-review используй два SKILL `K-BRAIN/SKILLS/code-review.md` и `K-BRAIN/SKILLS/ai-slops.md`.
Все текущие и будущие задачи записывай и по мере выполнения обновляй в `K-BRAIN/TODO.md`.
Используй только best practices.
В любой неуверенной ситуации остановись и уточни решение у меня, только потом переходи к реализации.
Для графиков и рисунков используй mermaid или генерацию через seaborn. Для сложных случаев можно писать ответ в виде .html файла.

Работай со мной в тесной связке, начиная с открытых вопросов и наброска плана, прежде чем приступать к его написанию.

## Workflow
QRSPI: Q→R→D→S→P→I. Нетривиальная задача — всегда. Тривиальное (one-liner, опечатка) — напрямую с 1 строкой объяснения. Переход между фазами — только с явного подтверждения пользователя. Артефакты задач — `TASKS/<slug>/`.

## Design Review
Дизайн-док `03-design.md` содержит секцию `## Comments`. Комментарии: `[human]` / `[agent] resolved`. Переход D→S — только при 0 открытых комментариев. Решения из комментариев — в `05-plan.md`.

## Artifacts
Именование: `<phase>-<type>-<slug>.<ext>`. Не переписываются задним числом (новые итерации — `-v2`). Ссылки на артефакты — в `05-plan.md`. Подробности — `ARTIFACTS.md`.

## Collaboration
Мышление — за человеком. Агент: факт / предположение / вопрос. Каждая фаза — место для pushback (минимум 2 гипотезы что может пойти не так). Дифф >200 строк → под-шаги с отдельным ревью.

## Context
Все решения, влияющие на код, фиксируются в `TASKS/<slug>/`. Subagents — артефакты в `artifacts/subagents/`, основная сессия ссылается, не пересказывает.

## Skills
- `SKILLS/development.md` — ленивый сеньор, anti-overengineering, фаза I
- `SKILLS/code-review.md` + `ai-slops.md` — ревью после каждого под-шага
- `SKILLS/comments.md` — правила комментариев в коде и дизайне
