# elliptic_v1 — первый decision path на Elliptic++ (2026-09-18)

Обучено `scripts/train_decision_path.py` (seed 72). Данные: `data/elliptic_raw` (только labeled: 46 564 tx, illicit = class 1). Сплит строго темпоральный: train 1..30 / valid 31..40 / test 41..49.

## Что внутри

- `gbdt.txt` (1.8 МБ) — LightGBM, `num_leaves=31` (parsimony: 63/127 выше точечно, но CI перекрывает ноль), 500 раундов, `scale_pos_weight` из дисбаланса.
- `calibrator_beta.joblib` — beta-калибровка (§7.5.3: ΔECE CI `[-0.0004, +0.0013]` пересекает ноль → tie → beta как устойчивая).
- `gbdt_meta.joblib` — 171 признак (165 табличных + графовые + темпоральные), имена колонок.
- `metrics.json` — полные цифры.

## Метрики (test, base rate 5.25%)

| Метрика | Значение | Смысл |
|---|---|---|
| PR-AUC | 0.647 | ранжирование: в ~12× лучше случайного (0.0525) |
| ROC-AUC | 0.877 | разделение классов уверенное |
| Brier | 0.031 → **0.025** (тривиальный 0.050) | вероятности вдвое лучше константы |
| ECE | 0.033 → **0.016** | калибровка хорошая (<0.1 с запасом) |

## Что это значит сейчас

Модель пригодна как скорер второй линии (Tier 2/3, analyst review), но не для автоблока: при recall, нужном для перехвата, precision даст поток ложных алертов сверх бюджета аналитиков. Главный факт — деградация valid→test: PR-AUC 0.96 → 0.65 при падении base rate 11% → 5.25%. Это темпоральный дрейф (§8), а не баг: типологии поздних шагов отличаются от ранних.
