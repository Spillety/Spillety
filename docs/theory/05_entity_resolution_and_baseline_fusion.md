# 5. Entity Resolution: кластеризация адресов и confidence-scored fusion

### Термины

| Термин | Определение |
|--------|-------------|
| Entity Resolution | Задача объединения адресов, с высокой вероятностью контролируемых одним субъектом (физическим или юридическим лицом, группой), в единый кластер |
| Cluster | Множество адресов, отнесённых к одному субъекту на основании эвристик или модели; базовая единица последующего анализа (профилирование, retrieval, скоринг) |
| CIOH | Common Input Ownership Heuristic: эвристика, согласно которой адреса, фигурирующие как входы одной транзакции в UTXO-модели, с высокой вероятностью принадлежат одному владельцу |
| Multi-signal fusion | Процедура объединения нескольких разнородных сигналов кластеризации в единую апостериорную оценку вероятности принадлежности пары адресов одному кластеру |
| Calibrated prior | Априорная вероятность, эмпирически оценённая и откалиброванная на размеченном ground truth (Elliptic++) |
| Copula | Функция, позволяющая специфицировать совместное распределение случайных величин через их маргинальные распределения и структуру зависимости |
| PR-curve | Precision-Recall кривая — зависимость точности (precision) от полноты (recall) при варьировании порога классификации |
| Operating point | Пороговое значение $\tau$, выбранное на PR-кривой в соответствии с заданной функцией стоимости |
| PR-AUC | Площадь под PR-кривой; интегральная мера качества ранжирования при дисбалансе классов |
| ECE | Expected Calibration Error — ожидаемая ошибка калибровки вероятностных предсказаний |
| Brier score | Среднеквадратичная ошибка между предсказанной вероятностью и фактическим бинарным исходом |
| Silhouette score | Метрика компактности и отделённости кластеров |
| Recall@K | Доля истинных соседей, попадающих в $K$ ближайших соседей в заданном пространстве |

## 5.1. Постановка задачи

В предшествующих разделах рассмотрено получение векторного представления (embedding) отдельного адреса посредством графовой нейронной сети и контрастивного обучения. Однако представление на уровне изолированного адреса обладает принципиальными ограничениями: один субъект может контролировать множество адресов (до $10^3$–$10^4$), и анализ каждого адреса независимо порождает нестабильный, зашумлённый сигнал с неполным покрытием.

**Entity resolution** определяется как задача отображения множества адресов $\mathcal{V}$ в разбиение $\mathcal{C} = \{C_1, \ldots, C_M\}$, где каждый кластер $C_m$ предположительно соответствует одному субъекту. Дальнейший анализ (профилирование поведения, retrieval, скоринг) осуществляется на уровне кластера, а не отдельного адреса.

Актуальность entity resolution для Spillety обусловлена тремя факторами:

1. **Стабильность сигнала.** Отдельный адрес может быть создан для единичной транзакции и не использоваться повторно; агрегированное поведение кластера отражает активность субъекта на протяжённом временном горизонте и обладает меньшей дисперсией.
2. **Полнота покрытия санкционных ограничений.** Если санкционный перечень содержит один адрес субъекта, контролирующего $N$ адресов, корректная кластеризация обеспечивает распространение санкционной метки на все $N$ адресов.
3. **Снижение шума.** Стохастический шум на уровне отдельного адреса усредняется при агрегации на уровне кластера (эффект, аналогичный бэггингу).

Формальная постановка: для каждой неупорядоченной пары адресов $(u,v) \in \mathcal{V} \times \mathcal{V}$ требуется оценить апостериорную вероятность $P(c_{uv}=1 \mid s_1, \ldots, s_k)$, где $c_{uv}=1$ — событие «$u$ и $v$ принадлежат одному кластеру», $s_1,\ldots,s_k$ — наблюдаемые сигналы кластеризации, и объединить адреса в кластеры при превышении вероятностью порога $\tau$.

Теоретически мы оцениваем наше решение вот так: PR-AUC, ECE, Brier, silhouette, recall@K, KS. Данный набор метрик обеспечивает оценку дискриминативной способности fusion-модели, калибровки вероятностных предсказаний, геометрического качества результирующих кластеров и устойчивости процедуры во времени.

## 5.2. Сигналы кластеризации

В литературе по анализу блокчейн-данных выделяют четыре класса методов кластеризации: эвристические, поведенческие, основанные на внешних данных и визуально-аналитические. Spillety использует комбинацию первых двух классов, дополненную anchor-относительными сигналами, с последующим статистически обоснованным объединением (fusion).

### 5.2.1. CIOH (Common Input Ownership Heuristic)

Для Bitcoin и иных блокчейнов с UTXO-моделью CIOH является доминирующим сигналом. Механика подписи транзакций в Bitcoin требует, чтобы все входы транзакции были подписаны приватными ключами, контролируемыми одним субъектом (за исключением специальных протоколов, см. ограничения ниже).

**Формально:** для транзакции $T$ с множеством входов $\{in_1, \ldots, in_n\}$:

$$
\forall i, j: \quad \text{addr}(in_i) \sim \text{addr}(in_j)
$$

где $\sim$ обозначает отношение «с высокой вероятностью принадлежат одному владельцу».

**Ограничения CIOH:**

- **CoinJoin.** Протоколы CoinJoin агрегируют входы от множества независимых пользователей в одной транзакции, что прямо нарушает предпосылку CIOH. Входы CoinJoin-транзакции не принадлежат одному субъекту.
- **Exchange hot wallets.** Централизованные биржи агрегируют средства тысяч пользователей на ограниченном множестве адресов, порождая ложные срабатывания CIOH при совместном расходовании.
- **Taproot / Schnorr signatures.** Переход к подписям Шнорра затрудняет установление факта подписания входов одним или несколькими субъектами по наблюдаемым данным транзакции, что снижает различимость CoinJoin и обычных транзакций.

**Эмпирическая калибровка confidence для CIOH.** На ground truth Elliptic++ оценивается условная вероятность $P(c_{uv}=1 \mid \text{CIOH})$. Точечная оценка находится в диапазоне $0.90$–$0.95$, однако не достигает единицы вследствие указанных ограничений. Интервальная оценка и калибровка осуществляются в рамках fusion-модели (раздел 5.3).

### 5.2.2. Поведенческие сигналы

Для блокчейнов с account-моделью (Ethereum и EVM-совместимые сети), где CIOH неприменима, используются поведенческие сигналы:

| Сигнал | Формальное определение | Эмпирическая информативность |
|--------|------------------------|-------------------------------|
| **Nonce sequence** | Последовательность транзакций с монотонно возрастающим nonce, сменяющая адрес-источник: $ \text{nonce}_A = n, n+1, n+2$ затем $\text{nonce}_B = n+3$ | Средняя |
| **Gas price pattern** | Совпадение предпочитаемого значения gas price (например, фиксированное $20$ gwei, характерное для конкретной реализации кошелька) | Средняя |
| **Temporal proximity** | Интервал между транзакциями адресов $u$ и $v$ удовлетворяет $\Delta t(u,v) < \epsilon$ (секунды — минуты) | Низкая–средняя |
| **Fee pattern** | Совпадение удельной комиссии (для Bitcoin: sat/vB) с точностью до квантования кошелька | Средняя |
| **Deposit address reuse** | Повторное использование одного депозитного адреса при взаимодействии с централизованной биржей | Высокая |

Каждый сигнал $s_i$ рассматривается как случайная величина с условными распределениями $P(s_i \mid c_{uv}=1)$ и $P(s_i \mid c_{uv}=0)$, оцениваемыми на ground truth (раздел 5.4).

### 5.2.3. Anchor-относительные сигналы

Если два адреса $u$ и $v$ демонстрируют близкие расстояния до одного anchor $a$ в embedding-пространстве ($\ \|z_u - z_a\|_2 \approx \|z_v - z_a\|_2$ и оба расстояния малы), это constituiрует слабый сигнал их взаимной принадлежности одному субъекту. Данный сигнал не является статистически независимым от геометрии embedding-пространства и от CIOH/поведенческих сигналов, что требует явного моделирования зависимости в fusion-модели. В Spillety anchor-относительные сигналы используются исключительно как дополнительные с пониженным весом, но не как первичные.

## 5.3. Проблема зависимых сигналов и методы fusion

### 5.3.1. Ограничения наивного байесовского подхода

Наивный байесовский классификатор (Naive Bayes) предполагает условную независимость сигналов при фиксированном классе:

$$
P(c \mid s_1, \ldots, s_k) \propto P(c) \prod_{i=1}^{k} P(s_i \mid c)
$$

где $c \in \{0,1\}$ — индикатор принадлежности одному кластеру.

**Нарушение предпосылки.** Эмпирически сигналы зависимы при условии $c$:
- CIOH и temporal proximity коррелируют, поскольку входы одной транзакции по определению находятся в одном блоке (одновременность).
- Gas price pattern и nonce sequence коррелируют как проявления единой реализации кошелька.

Игнорирование зависимости приводит к эффекту overconfidence: апостериорная вероятность систематически завышается (приближается к $0$ или $1$ сильнее, чем оправдано данными), что порождает ложные объединения (false merges) и деградирует PR-AUC и калибровочные метрики (ECE, Brier).

### 5.3.2. Copula-based fusion

**Определение.** Копула $C: [0,1]^k \to [0,1]$ — функция совместного распределения, связывающая маргинальные функции распределения $F_1, \ldots, F_k$ с совместным распределением $F$ согласно теореме Склара:

$$
F(x_1, \ldots, x_k) = C\bigl(F_1(x_1), \ldots, F_k(x_k)\bigr)
$$

Копула декомпозирует совместное распределение на маргинальные компоненты и структуру зависимости, позволяя моделировать зависимость сигналов без предположения о независимости и без спецификации многомерного параметрического семейства для исходных сигналов.

**Применение в Spillety.** Для каждого сигнала $s_i$ оцениваются маргинальные условные распределения $P(s_i \mid c=1)$ и $P(s_i \mid c=0)$ на ground truth. Затем параметрическое семейство копул $C_\theta$ калибруется на совместных наблюдениях сигналов. Апостериорная вероятность вычисляется с учётом копулы:

$$
P(c=1 \mid \mathbf{s}) = \frac{P(c=1) \cdot c_1\bigl(F_1(s_1\mid c=1),\ldots\bigr)}{P(c=1)\cdot c_1(\cdot) + P(c=0)\cdot c_0(\cdot)}
$$

где $c_1, c_0$ — плотности копул при $c=1$ и $c=0$.

**Выбор семейства копул.** Рассматриваются архимедовы копулы, наиболее распространённые в прикладном моделировании зависимости:

| Семейство | Параметр зависимости | Характеристика хвостовой зависимости |
|-----------|---------------------|--------------------------------------|
| Clayton | $\theta > 0$ | Нижняя хвостовая зависимость (совместные низкие значения) |
| Gumbel | $\theta \geq 1$ | Верхняя хвостовая зависимость (совместные высокие значения) |
| Frank | $\theta \in \mathbb{R}\setminus\{0\}$ | Симметричная зависимость без хвостовой асимметрии |

Выбор семейства осуществляется эмпирически по критериям раздела 5.7: максимизация PR-AUC и минимизация ECE/Brier на валидационной выборке, а также анализ эмпирической функции зависимости (rank-plot, хвостовая зависимость) на ground truth.

### 5.3.3. Logistic fusion

Альтернативная спецификация — логистическая регрессия на пространстве сигналов:

$$
P(c=1 \mid s_1, \ldots, s_k) = \sigma\!\left(\beta_0 + \sum_{i=1}^{k} \beta_i s_i\right), \quad \sigma(z) = \frac{1}{1+e^{-z}}
$$

**Преимущества:**
- Вычислительная простота и численная устойчивость; эффективная оптимизация с регуляризацией $L_1$/$L_2$.
- Интерпретируемость коэффициентов $\beta_i$ как логарифмов отношения шансов (log-odds ratio) при единичном приращении сигнала.
- Возможность отбора значимых сигналов посредством $L_1$-регуляризации (Lasso).

**Ограничение.** Логистическая спецификация предполагает линейность зависимости логарифма отношения шансов от сигналов. При наличии существенной нелинейности зависимости (например, пороговые эффекты CIOH) копула может обеспечить более высокую PR-AUC и лучшую калибровку (ECE, Brier).

**Базовая стратегия Spillety.** В качестве baseline используется logistic fusion; переход к copula-based fusion осуществляется при наличии статистически значимого улучшения по PR-AUC/ECE/Brier на валидации (см. раздел 5.7).

## 5.4. Калибровка приоров на ground truth

### 5.4.1. Elliptic++ как ground truth

Elliptic++ является единственным публично доступным набором данных с верифицированной разметкой Bitcoin-адресов на уровне кластеров.

| Параметр | Значение |
|----------|----------|
| Транзакций | 203 769 |
| Адресов | 822 942 |
| Временных шагов | 49 |
| Illicit адресов | 14 266 |
| Licit адресов | 251 088 |
| Unknown | 557 588 |
| Признаков на адрес | 56 |

**Содержание разметки:**
- Метки illicit / licit / unknown для каждого адреса (unknown — отсутствие ground truth, не эквивалентно licit).
- Кластеризация адресов, выполненная на основе multiple-input heuristic с ручной верификацией.
- Темпоральное разбиение на 49 шагов, обеспечивающее возможность walk-forward валидации.

**Ограничение.** Разметка illicit заведомо неполна (557 588 адресов имеют статус unknown). Следовательно, эмпирические оценки precision/recall, вычисленные на Elliptic++, являются нижними оценками истинных значений: часть false positives в действительности может соответствовать нераскрытым illicit-адресам.

### 5.4.2. Калибровка приоров и условных распределений

**Априорная вероятность кластеризации.** Оценивается эмпирически на обучающей части Elliptic++:

$$
\hat{P}(c=1) = \frac{|\{(u,v): c_{uv}=1\}|}{|\{(u,v): u \neq v\}|}
$$

Дополнительно оценивается темпорально-стратифицированный приор $\hat{P}(c=1 \mid t)$ для учёта нестационарности.

**Условные распределения сигналов.** Для каждого сигнала $s_i$ строятся эмпирические распределения $P(s_i \mid c=1)$ и $P(s_i \mid c=0)$ посредством ядерной оценки плотности или гистограммной аппроксимации на обучающей выборке. Данные распределения являются маргинальными входами для copula-модели и компонентами правдоподобия для logistic-модели.

**Протокол калибровки:**
1. Темпоральное разбиение Elliptic++ на train (шаги $1$–$35$) / validation (шаги $36$–$42$) / test (шаги $43$–$49$) без перемешивания, во избежание утечки будущей информации.
2. На train: оценка $\hat{P}(c=1)$, $\hat{P}(s_i \mid c)$ и калибровка параметров копулы / логистической регрессии.
3. На validation: выбор семейства копулы, гиперпараметров регуляризации и operating point $\tau$ по метрикам раздела 5.7.
4. На test: финальная оценка PR-AUC, ECE, Brier, silhouette, recall@K, KS; отчётность по всем метрикам.

Теоретически мы оцениваем наше решение вот так: PR-AUC, ECE, Brier — калибровка приоров и выбор между copula и logistic fusion валидируются по PR-AUC (дискриминация) и ECE/Brier (калибровка) на hold-out временном срезе Elliptic++.

## 5.5. Выбор operating point

### 5.5.1. PR-кривая

Для каждого порогового значения $\tau \in [0,1]$ на выходе fusion-модели вычисляются:

$$
\text{Precision}(\tau) = \frac{TP(\tau)}{TP(\tau) + FP(\tau)}, \qquad \text{Recall}(\tau) = \frac{TP(\tau)}{TP(\tau) + FN(\tau)}
$$

где $TP$, $FP$, $FN$ — числа истинно положительных, ложно положительных и ложно отрицательных пар при пороге $\tau$. Множество точек $\{(\text{Recall}(\tau), \text{Precision}(\tau))\}_{\tau}$ образует PR-кривую.

![pr_curve_entity_resolution](./files/5-5-1_pr_curve_entity_resolution.png)

*PR-кривая entity resolution. Каждая точка соответствует порогу $\tau$; отмеченная точка — operating point, минимизирующий функцию стоимости. Площадь под кривой (PR-AUC) является интегральной мерой качества ранжирования.*

Теоретически мы оцениваем наше решение вот так: PR-AUC — площадь под PR-кривой вычисляется на тестовом срезе Elliptic++; более высокое значение PR-AUC свидетельствует о лучшей способности fusion-модели ранжировать пары адресов по вероятности принадлежности одному кластеру.

### 5.5.2. Функция стоимости и operating point

Порог $\tau$ выбирается не по эвристическому квантилю, а посредством минимизации ожидаемой стоимости ошибок:

$$
\text{Cost}(\tau) = C_{FP} \cdot FP(\tau) + C_{FN} \cdot FN(\tau)
$$

где:
- $C_{FP}$ — стоимость ложного объединения (false merge): порождение ложного кластера, влекущее downstream-ошибки (ложные алерты, reputational damage);
- $C_{FN}$ — стоимость пропуска истинного объединения (false split): фрагментация субъекта на несколько кластеров, влекущая неполноту покрытия.

Соотношение $C_{FN}/C_{FP}$ специфицируется исходя из бизнес-требований Spillety (консервативная стратегия минимизации ложных алертов соответствует $C_{FP} > C_{FN}$).

**Operating point:**

$$
\tau^* = \arg\min_{\tau \in [0,1]} \text{Cost}(\tau)
$$

Теоретически мы оцениваем наше решение вот так: ECE, Brier — после фиксации $\tau^*$ по PR-кривой дополнительно оценивается калибровка вероятностных предсказаний fusion-модели посредством ECE и Brier score; более низкие значения указывают на соответствие предсказанных вероятностей эмпирическим частотам, что необходимо для корректной интерпретации $\tau^*$ как вероятностного порога.

### 5.5.3. Ограничение на размер кластера

Для предотвращения феномена cluster collapse (вырожденного решения, при котором значительная доля адресов объединяется в один гигантский кластер при высоком отношении $C_{FN}/C_{FP}$) вводится экзогенное ограничение:

$$
\text{max\_cluster\_size} = 10^6
$$

При превышении кластером данного размера порог $\tau$ локально повышается для соответствующего подграфа (adaptive thresholding). Ограничение является эмпирической регуляризацией без строгого теоретического обоснования, но необходимой для обеспечения вычислительной и семантической состоятельности.

![cluster_size_distribution](./files/5-5-2_cluster_size_distribution.png)

*Эмпирическое распределение размеров кластеров в блокчейн-данных. Наблюдается степенной закон (power law): преобладание мелких кластеров ($1$–$5$ адресов) и тяжёлый хвост крупных кластеров (биржи, миксеры). Левая панель — линейная шкала (акцент на хвост), правая — двойная логарифмическая шкала (демонстрация степенного закона).*

### 5.5.4. Калибровка операционного порога по PR-кривой: варианты

Рассматриваются следующие варианты выбора $\tau^*$:

| Вариант | Критерий выбора $\tau$ |
|---------|------------------------|
| Фиксированный квантиль (baseline) | $\tau$ как $95$-й процентиль предсказанных вероятностей на train |
| Cost-optimal по PR-кривой | $\tau^* = \arg\min \text{Cost}(\tau)$ при заданных $C_{FP}, C_{FN}$ |
| PR-AUC-optimal (F1-max) | $\tau$ максимизирующий $F_1(\tau) = 2PR/(P+R)$ — частный случай cost-optimal при $C_{FP}=C_{FN}$ |
| Constrained cost-optimal | Cost-optimal при ограничении $\text{max\_cluster\_size} = 10^6$ |

Выбор между вариантами осуществляется по метрикам раздела 5.7 на валидационной выборке.

## 5.6. Инкрементальное обновление кластеров

### 5.6.1. Постановка

Кластерная структура должна поддерживаться в актуальном состоянии при непрерывном поступлении новых транзакций. Полная рекластеризация графа на каждом блоке вычислительно недопустима (сложность $O(|\mathcal{V}|^2)$ попарных сравнений).

### 5.6.2. Решение: структура union-find

Для инкрементального поддержания кластеров используется структура данных **union-find** (disjoint-set union, DSU) с эвристиками сжатия пути (path compression) и объединения по рангу (union by rank):

- **Find($v$):** определение идентификатора кластера, содержащего адрес $v$.
- **Union($u,v$):** объединение кластеров, содержащих $u$ и $v$, в один.

**Инкрементальный протокол:**
1. Появление нового адреса $v_{\text{new}}$: создание одноэлементного кластера $\{v_{\text{new}}\}$.
2. Для каждой новой транзакции $T$, затрагивающей адреса $\{v_1,\ldots,v_k\}$: вычисление апостериорных вероятностей $P(c_{v_i v_j}=1 \mid \mathbf{s})$ для всех пар.
3. Если $P(c_{v_i v_j}=1 \mid \mathbf{s}) > \tau^*$: выполнение $\text{Union}(v_i, v_j)$.
4. Обновление метаданных кластера: размер, центроид embedding'ов, агрегированные поведенческие признаки.

**Вычислительная сложность.** Амортизированная сложность операции Find/Union составляет $O(\alpha(|\mathcal{V}|))$, где $\alpha$ — обратная функция Аккермана, практически константная ($\alpha < 5$ для всех физически реализуемых $|\mathcal{V}|$).

### 5.6.3. Периодическая полная рекластеризация

Инкрементальная процедура накапливает ошибки (error drift) вследствие локальности решений Union. Для коррекции предусмотрена периодическая полная рекластеризация:

1. Фиксация скользящего окна адресов за последние $N$ месяцев.
2. Полный пересчёт сигналов $\mathbf{s}$ и переоценка параметров fusion-модели на актуальном ground truth.
3. Построение кластеров с нуля (de novo) на основе текущего $\tau^*$.
4. Сопоставление с инкрементальными кластерами; разрешение расхождений в пользу de novo-кластеризации при превышении расхождения порога.

**Триггер рекластеризации:** календарный (ежемесячно) или адаптивный — при превышении KS-статистикой между распределениями размеров/характеристик кластеров на последовательных окнах критического значения (см. раздел 5.7).

## 5.7. Протокол выбора модели fusion и валидации

Данный раздел специфицирует пространство проектных решений и протокол их эмпирического сравнения. Теоретически мы оцениваем наше решение вот так: PR-AUC, ECE, Brier, silhouette, recall@K, KS — каждая кандидатная конфигурация оценивается по полной совокупности метрик.

### 5.7.1. Пространство проектных решений

| Фактор | Рассматриваемые варианты |
|--------|--------------------------|
| Модель fusion | (a) logistic fusion (baseline); (b) copula-based fusion |
| Семейство копулы (при выборе (b)) | Clayton, Gumbel, Frank |
| Набор сигналов | CIOH only; CIOH + поведенческие; CIOH + поведенческие + anchor-относительные |
| Регуляризация logistic | $L_1$ ($\ell_1$), $L_2$ ($\ell_2$), Elastic Net; коэффициент $\lambda \in \{10^{-4},10^{-3},10^{-2},10^{-1}\}$ |
| Порог $\tau$ | Фиксированный квантиль vs cost-optimal по PR-кривой vs constrained cost-optimal (см. раздел 5.5.4) |

### 5.7.2. Метрики и критерии сравнения

| Метрика | Что измеряет | Критерий предпочтения |
|---------|-------------|-----------------------|
| **PR-AUC** | Интегральная дискриминативная способность ранжирования пар по $P(c=1 \mid \mathbf{s})$ | Максимизация; статистическая значимость разности проверяется тестом ДеЛонга / bootstrap |
| **ECE** | Калибровка: соответствие предсказанных вероятностей эмпирическим частотам | Минимизация; разбиение на $M=15$ бинов |
| **Brier score** | Совокупная ошибка калибровки и дискриминации ($0$ — идеал) | Минимизация |
| **Silhouette** | Геометрическая компактность и отделённость результирующих кластеров в embedding-пространстве | Максимизация среднего $\bar{s}$; вычисляется на тестовом срезе с известными кластерами |
| **Recall@K** | Качество retrieval: доля истинных членов кластера в $K$ ближайших соседях по embedding-расстоянию внутри предсказанного кластера | Максимизация при $K \in \{10,50,100\}$ |
| **KS-тест** | Устойчивость распределений характеристик кластеров (размеры, внутрикластерные расстояния) между временными срезами | Отсутствие значимых сдвигов ($p \geq 0.05$); при $p < 0.01$ — сигнал к рекластеризации |

Теоретически мы оцениваем наше решение вот так: silhouette — средний silhouette score результирующих кластеров на hold-out множестве; более высокое значение указывает на геометрически более когерентные кластеры, порождаемые fusion-моделью.

Теоретически мы оцениваем наше решение вот так: recall@K — для каждого адреса из тестового множества измеряется доля истинных сокластерников, попадающих в top-$K$ ближайших соседей по embedding-расстоянию внутри предсказанного кластера.

Теоретически мы оцениваем наше решение вот так: KS — двухвыборочный KS-тест применяется к распределениям размеров кластеров и внутрикластерных расстояний на последовательных временных окнах; отсутствие отвержения $H_0$ свидетельствует о стабильности процедуры entity resolution.

### 5.7.3. Процедура выбора

1. **Фильтрация по дискриминации.** Отсечение конфигураций, уступающих лидеру по PR-AUC более чем на $0.01$ (абсолютная шкала) при $p < 0.05$ (bootstrap, $B=1000$ реплик).
2. **Отбор по калибровке.** Среди оставшихся — минимизация ECE и Brier; предпочтение конфигурациям с $\text{ECE} < 0.05$ и минимальным Brier.
3. **Контроль геометрии.** Проверка silhouette и Recall@K: конфигурации, деградирующие $\bar{s}$ или Recall@K более чем на $5\%$ относительно logistic baseline, штрафуются независимо от PR-AUC.
4. **Проверка стабильности.** KS-тест на последовательных временных окнах validation; конфигурации с $p < 0.01$ (значимый дрейф) отклоняются.
5. **Правило парсимонии.** При статистической неразличимости по совокупности метрик предпочтение отдаётся более простой модели в порядке: logistic $>$ Frank $>$ Clayton/Gumbel (Frank — симметричная зависимость, минимальная априорная специфика хвостов).

**Ожидаемые эффекты (гипотезы для проверки):**
- Copula с семейством Clayton/Gumbel превосходит logistic и Frank при наличии выраженной хвостовой зависимости сигналов (эмпирически: CIOH и temporal proximity демонстрируют нижнюю хвостовую зависимость — Clayton).
- Добавление anchor-относительных сигналов повышает PR-AUC на $1$–$3$ п.п., но может ухудшать ECE при некорректном учёте зависимости; эффект валидируется по Brier.
- Cost-optimal порог по PR-кривой превосходит фиксированный квантиль по взвешенной стоимости $\text{Cost}(\tau)$ и по ECE (квантиль не учитывает асимметрию $C_{FP}/C_{FN}$).

## 5.8. Ограничения

1. **Ложные срабатывания CIOH.** Протоколы CoinJoin, exchange hot wallets и транзакции Taproot систематически нарушают предпосылку CIOH, порождая ложные объединения. Mitigation — пониженный вес CIOH-сигнала при детекции CoinJoin-паттернов и учёт зависимости через копулу, однако полностью устранить ошибку невозможно.

2. **Неполнота и доменная ограниченность ground truth.** Elliptic++ охватывает исключительно Bitcoin-адреса и содержит неполную разметку illicit (unknown $= 557\,588$). Перенос калиброванных приоров на Ethereum/EVM-сети вносит дополнительную ошибку вследствие различия механизмов кластеризации (отсутствие CIOH). Требует доменной адаптации с отдельной калибровкой на Ethereum-специфичных сигналах.

3. **Риск cluster collapse.** При высоком отношении $C_{FN}/C_{FP}$ (штраф за пропуск объединения существенно превышает штраф за ложное объединение) fusion-модель склонна к вырожденному решению — объединению значительной доли графа в один кластер. Экзогенное ограничение $\text{max\_cluster\_size}=10^6$ смягчает, но не устраняет проблему теоретически.

4. **Темпоральный дрейф.** Появление новых протоколов (Taproot, ZK-mixers, account abstraction) изменяет распределения сигналов, что деградирует PR-AUC и калибровку (рост ECE/Brier). Детекция дрейфа осуществляется KS-тестом; mitigation — периодическая рекластеризация и переоценка fusion-модели (раздел 5.6.3).

5. **Вычислительная сложность полной рекластеризации.** Полная рекластеризация $800\,000+$ адресов с попарным вычислением fusion-оценок требует значительных ресурсов ($O(|\mathcal{V}|^2)$ в наивной реализации; на практике — $O(|\mathcal{E}|)$ с pruning по сигналам). Union-find обеспечивает эффективную инкрементальную альтернативу, но ценой накопления ошибок, требующих периодической коррекции.

**Резюме.** Entity resolution в Spillety формулируется как задача multi-signal fusion с калибровкой на ground truth Elliptic++ и выбором operating point по PR-кривой с учётом функции стоимости.

| Компонент | Функциональная роль | Наблюдаемый эффект |
|-----------|---------------------|---------------------|
| CIOH | Доминирующий сигнал для UTXO-блокчейнов | Высокая условная вероятность $P(c=1\mid\text{CIOH})$ |
| Поведенческие сигналы | Дополнительные сигналы для account-модели (nonce, gas price, temporal) | Средняя информативность; компенсируют отсутствие CIOH |
| Copula / logistic fusion | Статистически корректное объединение зависимых сигналов | Калиброванный posterior $P(c=1\mid\mathbf{s})$; выбор семейства Clayton/Gumbel/Frank по PR-AUC/ECE/Brier |
| Elliptic++ | Единственный публичный ground truth для калибровки | Эмпирические приоры $\hat{P}(c)$, $\hat{P}(s_i\mid c)$ |
| PR-кривая + cost-функция | Выбор operating point $\tau^*$ | Оптимальный порог с учётом асимметрии $C_{FP}/C_{FN}$ и ограничения $\text{max\_cluster\_size}$ |
| Union-find | Инкрементальное поддержание кластеров | Амортизированная сложность $O(\alpha(|\mathcal{V}|))$ на операцию |
| Валидация | Теоретически мы оцениваем наше решение вот так: PR-AUC, ECE, Brier, silhouette, recall@K, KS | Комплексная диагностика: дискриминация, калибровка, геометрия, стабильность |

**Практические следствия:**
- CIOH эффективен для Bitcoin, но уязвим к CoinJoin, exchange hot wallets и Taproot; требует моделирования зависимости.
- Для Ethereum используются поведенческие сигналы (nonce sequence, gas price pattern, temporal proximity, fee pattern, deposit reuse).
- Зависимость сигналов учитывается через copula (Clayton/Gumbel/Frank) или logistic fusion; выбор — по PR-AUC/ECE/Brier на валидации.
- Elliptic++ — единственный публичный ground truth; калибровка требует темпорального разбиения без утечки.
- Теоретически мы оцениваем наше решение вот так: PR-AUC, ECE, Brier, silhouette, recall@K, KS — каждая конфигурация $\{\text{copula vs logistic},\; \text{Clayton/Gumbel/Frank},\; \tau \text{ по PR-кривой}\}$ подлежит сравнению по полной совокупности данных метрик, включая PR-AUC (дискриминация), ECE/Brier (калибровка), silhouette/Recall@K (геометрия кластеров) и KS-тест (темпоральная стабильность).
